# Phase 6B — Animation refinement

This phase improves the existing project-owned skeletal character asset and animation controller. It is still a lightweight stylized character, not a motion-captured or artist-final character.

## What changed

- Refined the in-place walk/run gait with counter-swinging arms, subtle pelvis/spine motion, and a more consistent phase convention.
- Added `WalkStart`, `WalkStop`, `RunStart`, `RunStop`, and `IdleLook` clips. The controller blends into these clips when movement starts/stops or during quiet idle moments.
- Improved sit-down/stand-up anticipation and balance movement.
- Added light ankle/foot counter-rotation during locomotion to reduce the appearance of tilted soles when the knees bend.
- Added low-amplitude vertical response to walk/run animation while keeping the gameplay root unchanged, avoiding root-motion double movement in multiplayer.
- Timed the bed tilt to the `LieDown` and `WakeUp` clips instead of tilting the entire model immediately. Seated states no longer lower the entire character by 0.3 metres.
- Fixed `showFace={false}` so it recognizes the actual eye/brow/mouth node names in the GLB.
- Retained the old character as the Suspense/error fallback.

## Character asset

`client/public/models/characters/life-sim-donghua-base.glb` now contains 25 named clips on the same 19-joint glTF skeleton. The model remains lightweight for mobile use and the new clips are generated by `tools/generate_lifesim_donghua_avatar.py`.

## Test checklist

1. Run `npm install` then `npm run build` from the project root.
2. Start a new session and check that the GLB loads with no failed network requests.
3. Stand still for several seconds: verify subtle idle movement and occasional look-around.
4. Walk, stop, walk again, then transition between walk and run repeatedly. The feet should look flatter and the body should not slide from animation root motion.
5. Sit on a sofa, use a computer, finish the activity, and stand up. Check that the pelvis remains close to the furniture seat rather than sinking.
6. Sleep for a full interaction and wake up. Confirm that lie-down and wake-up tilt align with the clip timing and the character ends upright.
7. Test another player client and mobile viewport, since remote players use the same animation component.
8. Check appearance customisation and the `showFace` flag.

## Remaining limitations

The current asset uses procedural mesh geometry and a 19-joint skeleton, without fingers, facial blendshapes, true foot locking, a physics-driven cloth system, or motion capture. The foot counter-rotation is a visual correction, not full inverse kinematics. Exact hand contact still requires authored interaction clips and/or an IK target system. A more polished character should eventually replace the lightweight generated model while preserving the named animation interface.
